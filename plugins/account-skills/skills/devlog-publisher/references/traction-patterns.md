<blog_formats>
High-performing technical blog post formats for 2025-2026:

1. **"I Tried X for Y Days" Report** — Personal experiment with measurable results, before/after comparison, honest assessment including downsides. Example: "I Used Claude Code for 30 Days to Build My Entire Backend — Here's What Actually Happened"

2. **The Deep-Debug War Story** — Start with the symptom, walk through the investigation step-by-step, reveal the surprising root cause. Example: "Why My Docker Builds Were 10x Slower on Tuesdays (A Debugging Story)"

3. **Contrarian Technical Take** — Challenge conventional wisdom with evidence, show real results that contradict popular advice. Example: "Stop Writing Unit Tests for AI-Generated Code — Here's What to Do Instead"

4. **The How-I-Built-It Walkthrough** — Complete build log with every decision explained, real code, real terminal output, real mistakes. Example: "Building a Production MCP Server From Scratch in 4 Hours"

5. **Tool/Workflow Comparison (with receipts)** — Actual side-by-side on the same task, include timing, output quality, edge cases. Example: "Claude Code vs Cursor vs Copilot: Building the Same Feature Three Times"
</blog_formats>

<twitter_patterns>
Patterns that work for X/Twitter developer threads:

- **Hook tweet**: Surprising number, contrarian claim, or "I just discovered..." opener
- **Thread length**: 7-12 tweets optimal for technical content
- **Code in threads**: Describe what screenshots would show (readers fill in visually)
- **Each tweet standalone**: Should make sense if someone only sees that one tweet
- **Final tweet**: CTA + link + "What's your experience?" question
- **Engagement multiplier**: Tag relevant tools/companies (not spammy, just 1-2)
</twitter_patterns>

<linkedin_triggers>
Engagement triggers for engineering content on LinkedIn:

- **Pattern interrupt first line**: "I stopped doing code reviews. Here's why."
- **Short paragraphs**: 1-2 sentences each, lots of whitespace
- **Personal narrative**: "I" statements, specific projects, named tools
- **Technical credibility**: Include ONE specific metric or result
- **End with question**: Not rhetorical — genuinely invite technical discussion
- **Hashtags**: Max 3, placed at end, relevant (#ClaudeCode #DevTools #AIEngineering)
- **Avoid**: Humble bragging, "Excited to announce", listicles
</linkedin_triggers>

<newsletter_patterns>
Subject line patterns with high open rates:

- Curiosity gap: "The debugging trick I wish I knew 5 years ago"
- Specific number: "3 Claude Code patterns that saved me 8 hours this week"
- Direct address: "You're probably overcomplicating your MCP servers"
- Preview text should complement (not repeat) the subject line
</newsletter_patterns>

<content_gaps>
